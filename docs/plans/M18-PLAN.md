# M18 · 习惯体系

状态：规划完成，待开工（2026-11-26）
目标：让习惯具备与任务一致的组织能力——一级分组、可拖拽排序、可折叠、可编辑图标与 inline 标题；数据模型升级到 schema v4 且旧数据无损迁移。

## 范围

本迭代只做反馈项 #1（习惯部分）与 #16；#11 重复完成提示、#24 逾期语义仍在待调研清单，#10 主题由外部团队负责。

| 项 | 内容 |
|---|---|
| #16 | 新增独立 `habit_group`（一级分组，不做两层）；习惯加 `group_id`；分组 CRUD、拖拽排序、折叠状态持久化；旧习惯迁入「未分组」；schema v4 |
| #1 | 习惯标题 inline 编辑；图标从名称推导升级为「最近使用 8 个 + 常用 emoji 矩阵（60–80 个，不做搜索）」；存 `habit.icon` |

## 关键决策（用户 2026-11-25 已确认）

- 采用方案 B：新增独立 `habit_group`，不复用任务 `list/group`；只做一级分组。
- 旧习惯迁移到「未分组」，迁移必须可回滚；沿用 M6 的备份轮转与迁移演练流程。
- 图标选择不做搜索、不引入第三方 emoji 库；内置精选矩阵 + 最近使用。
- 交互与任务 Tab 对齐：分组标题支持重命名，习惯可拖入分组，折叠态写入 localStorage。
- 分组/图标是 Host 数据模型的一部分，不能像现在这样只按名称推导（`client-v2/40-habits.js` 现有注释明确说 Host 无分组字段）。

## 验收标准

- [ ] schema v3 → v4 迁移无损：旧习惯、打卡记录、暂停/归档状态全部保留，重复迁移幂等。
- [ ] 分组可新建、重命名、删除；删除分组时习惯回到「未分组」，不丢数据。
- [ ] 分组与习惯均可拖拽排序，刷新/重启后顺序保持。
- [ ] 分组折叠状态按 Tab 持久化，重开恢复。
- [ ] 习惯标题可 inline 编辑并保存；空标题被拒绝且有可见提示。
- [ ] 图标：默认按名称推荐；可从矩阵选择；最近使用 8 个；选择后持久化并在列表/详情/统计一致显示。
- [ ] 旧数据（无 `group_id`/`icon`）读取时不崩溃，显示「未分组」与推荐图标。
- [ ] 全仓 `npm test` 通过；新增迁移、CRUD、排序、图标选择的单元/集成测试。
- [ ] `npm run check` 通过；backlog #1/#16 带证据更新；STATUS 更新。

## 风险

- schema 迁移是不可逆操作：先在真实数据副本上演练，确认备份与回滚，再动生产数据。
- 习惯 Tab 现有布局较密，加分组栏后窄窗可能挤压；先做只读分组渲染，再加拖拽。
- Agent 工具参数变更会影响已有调用；分组参数必须可选，默认行为不变。
